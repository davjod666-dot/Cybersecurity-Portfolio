# Risk & Control Assurance

This section connects technical implementation to governance questions: what risk a control addresses, how it was validated, and which limitations remain.

[**Worked example: host-hardening control register**](Host-Hardening-Control-Register.md)

The worked example uses configuration checks and controlled test results from a personal Linux workstation. It demonstrates a reporting approach; it does not claim enterprise compliance or full-system assurance.

## Control-record structure

1. Define the objective and scope.
2. Describe the implemented control.
3. Link the validation evidence and capture date.
4. Record what the test covers and what it does not.
5. Assign ownership and follow-up for outstanding questions.
